# UI Visual System v1.0 — Specification Corrections and Decisions

**Version audited:** Google Drive files dated 2026-11-18; code baseline `11c86c04471ff1094122b4a83fca5f59890271b4`.

Use this document as a **stage-0 correction overlay**, not as an unapproved overwrite of the source design documents.

| ID | Original premise / conflict | Evidence or risk | Corrected implementation constraint | Decision state |
|---|---|---|---|---|
| E01 | Icon document declares 78 total, P0=38/P1=29/P2=11 | Enumerated entries A01–H06 total 78, P0=42/P1=27/P2=9 | Track **42 / 27 / 9** manifest entries. State variants and mirrored shapes may need more PNGs than entries. | Confirmed by inventory |
| E02 | A 40×40 visual button with 4px spacing is treated as a 44×44 touch target | Spacing does not enlarge a node's hit rectangle; Godot units, source PNG pixels, screen pixels and iPad points are not interchangeable | Set the actual minimum usable target using device-scale validation (44pt design goal); size background and transparent hit area separately. Avoid overlapping targets. | Stage-1 engineering rule |
| E03 | Compact 16×16 PNG is proposed at 24×24 while non-integer scaling is prohibited | 16→24 = 1.5× | Use 16→32, or create a dedicated 12→24 asset where 24 output is essential. Verify the nearest-neighbor import/render path. | Confirmed mathematical contradiction |
| E04 | `PaletteGrid.gd` assumed to draw swatch rectangles | `src/Palette/PaletteSwatch.gd::_draw()` actually draws borders/highlights via `draw_rect()` | Implement pixel outline rendering in the swatch drawing component; let PaletteGrid retain data, layout, pointer and selection responsibilities. | Confirmed in source |
| E05 | A universal white specular highlight is painted inside every color swatch | It changes the perceived selected paint color | Keep swatch's data-color region unmodified; put any highlight into separate chrome, not across color pixels. Support transparent checker presentation. | Proposed product clarification |
| E06 | Global ban on black, square pixels or softened rendering | Source canvas art, imported artwork, color samples and preview must remain exact; ban concerns **UI shell** | Restrict geometric, palette and blur prohibitions to decorative UI chrome. Never recolor or round a user's canvas pixels. | Stage-1 engineering rule |
| E07 | Fixed 4 columns in Gallery | `ProjectGallery.gd` has `LANDSCAPE_COLUMNS=6`, `PORTRAIT_COLUMNS=4` and layout reflow | Preserve orientation/adaptive columns; evaluate small split view based on *available* width, not just orientation. | Confirmed existing behavior; adaptive target |
| E08 | Proposed UI3 48px quick strip starts by replacing entire current panel | `WorkspaceUIProfile3.gd` has 100px fixed strip, tool-option value bindings, timeline bounds, and `WorkspaceSurface.gd` floating exclusion | Keep fixed anchor, source Range binding, reservation/exclusion and window priority; replace presentation only. Preserve UI3 active-tool-dependent visibility. | Confirmed existing contract |
| E09 | UI3 size rail caps at 128px and assumes all tools share a fixed scale | Current UI3 quick slider reads the original tool's `Range` and can expose larger maxima; brush types may use non-pixel units | Define improved 1–16 precision *without clamping the underlying tool's real range* or removing its unit suffix. Require a round-trip value test. | Stage-3 engineering rule |
| E10 | UI1 scrubby input should always be horizontal | Recent tool-option code explicitly supports a vertical drag mode: `ValueSlider.gd::configure_tool_vertical_drag()` | Preserve accepted vertical drag for tool-option controls. Unify styling without resetting established touch behavior. | Confirmed previous product decision |
| E11 | Palette toolbar icon list implies add/remove controls are foreground UI | `PalettePanel.tscn` contains AddColor and DeleteColor nodes, but AddColor is explicitly hidden; earlier product design removed add/remove buttons from default toolbar | Inventory legacy assets, but do **not** bring hidden buttons back merely to meet icon coverage. Use current palette interaction as the authoritative product behavior. | Confirmed conflict |
| E12 | Selection clipboard actions should be moved into a long-press menu only | Existing global selection floating action workflow already provides cut/copy/paste/delete; UI3 and other profiles must agree | Preserve the global selection context toolbar and delete action; remove only redundant top-bar controls after confirming no loss of discoverability. | Product interaction protection |
| E13 | UI layout profiles are just a flat `UI 1/3/4` selector | `WorkspaceUIProfileController.gd` already persists profile-specific state and handles removed UI2 | New 3-segment graphic selector must call current profile switching path; do not create a second profile state source. | Confirmed existing contract |
| E14 | One absolute default theme can simply replace all themes | `Themes.gd` supports system, light, dark, OLED and custom themed behavior; `WorkspaceVisualTheme.gd` derives its colors from active Theme | Stage 1 should build a bounded Phosprite theme adaptation layer and explicit policy for legacy/custom themes; never silently break them. | Architecture decision for stage 1 |
| E15 | Color budget (76/18/4.5/1.5) can be measured on any full screen image | User artwork, palette colors and preview dominate an editing screenshot | Exclude canvas art, color picker and imported reference imagery when evaluating shell-color coverage. Measure comparable controlled screenshots. | QA clarification |
| E16 | Fixed nine-slice margins alone prove R10/R6/R4 are crisp | Texture scale, Godot viewport scaling, filters, alpha edges and corners can change the result | Treat `StyleBoxTexture`/nearest-neighbor as an implementation proposal; verify on iPad rather than blanket replacing every StyleBox. | Stage-1 spike required |
| E17 | Strict 12/16/20/24 text sizes can replace every existing size without risk | Project Gallery has 11px and 13px override text; past iOS font regressions affected glyph rendering | Choose per-control font role, test Chinese/English, punctuation, numbers, fallback and dynamic layouts before broad replacement. | Confirmed code + QA protection |
| E18 | Every manifest entry is necessarily enabled in the iPad UI | `WorkspaceUIProfile3.gd` excludes certain tools from the iOS taskbar; some asset paths are old, hidden or share an icon | Create assets for supported/shared semantics, but do not reintroduce removed commands or invent new function entry points. Record live-usage separately. | Engineering rule |
| E19 | Floating-window drag strip may freely take the top 36px from all controls | `WorkspaceModule.gd` has headerless resize hit regions and Timeline special resize affordances | Preserve existing window movement and resize contracts; make header/resize geometry state-dependent. | Stage-3 engineering rule |
| E20 | 36×36 timeline cell size is entirely new | `src/UI/Timeline/CelButton.tscn` already has `custom_minimum_size = Vector2(36,36)` | Stage 4 focuses on style, selected-state shape and verified hit areas; do not unnecessarily change established cell grid sizes. | Confirmed existing behavior |

## Design freeze constraints for next phase

- Visual identity proposal: Sunny Cream + Twilight Berry; ink `#282C40`, primary blue `#4BA3FF`, reserved coral `#FF7863`. **Not applied yet**.
- Pixel chrome style tier targets: R10 / R6 / R4. Verify with real texture sizes and layout scaling before broad migration.
- Keep functional source of truth in original tools, palette model, project records and Workspace layout store.
- Do not modify touch gesture priorities solely to fit an illustration.
- Before replacing an asset, prove its *live reference*, its selected/disabled/hover state and its accessibility label.
- The source files in Drive remain unchanged in this stage; corrections are tracked here for implementation review.
